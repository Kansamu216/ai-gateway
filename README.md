# ai-gateway

把**桌面客户端的模型额度**变成一个跑在 NAS / 服务器上的 **OpenAI 兼容接口 + 网页控制台**。

局域网里任何设备（Cherry Studio / Open WebUI / LobeChat / Cursor / 手机 App）填一个地址、一把 Key 就能用。

```
┌─────────────────────────────────────────────────────┐
│  NAS / 服务器                                        │
│                                                     │
│   :8790  OpenAI 兼容接口  ← 客户端连这个             │
│   :8792  网页控制台       ← 浏览器连这个             │
│                                                     │
│   两个进程：代理（数据面）+ 控制台（管理面）          │
│   控制台负责拉起/重启代理，代理挂了不影响管理页       │
└─────────────────────────────────────────────────────┘
```

> ⚠️ **这不是官方 API。** 它复用桌面端已登录的会话转发请求，会受客户端
> 校验策略、账号额度、上游目录变化的影响。**用之前请先读
> [限制与风险](#限制与风险)**。

---

## 特性

- **一个地址接所有客户端** —— 标准 OpenAI 协议，支持流式、工具调用、
  并行工具调用、图片输入。
- **网页控制台** —— 看额度、看用量、发 Key、换凭据，不用碰命令行。
- **网页登录** —— 在控制台点一下就能完成上游账号登录，**密码不经过本机**。
- **零依赖** —— 两个纯 Node 文件，只用 `node:` 内建模块，镜像无需 `npm install`。
- **Agent 友好** —— 并发按上游真实能力排队、采样参数按官方规范校验、
  429 带 `Retry-After`（见 [针对 Agent 场景做的优化](#针对-agent-场景做的优化)）。

## 快速开始

```bash
# 1. 拿到代码
git clone <本仓库地址> && cd ai-gateway

# 2. 在已登录客户端的电脑上导出凭据（见「准备凭据」）
node export-auth.mjs --print-key          # 取 AtRest 密钥（推荐）
# 或直接导出明文：
node export-auth.mjs --auth-file <登录文件路径> --out ./data/auth.json

# 3. 起服务
docker compose up -d --build
docker compose logs -f | grep 口令        # 拿首次生成的管理口令

# 4. 打开控制台
#    http://<你的NAS地址>:8792
```

在控制台里完成三件事就能用了：**登录上游账号 → 生成 API Key → 把地址和 Key 填进客户端**。

## 日常怎么用

### 1. 加一台设备

浏览器打开控制台 → **API Key** → 填个设备名（`ipad`、`客厅电视`）→ 生成 → 复制弹出来的 Key。

### 2. 在客户端里配置

以 Cherry Studio 为例：「设置 → 模型服务 → 添加 → OpenAI」

```
API 地址: http://<你的NAS地址>:8790/v1
API 密钥: wb-xxxxx（刚才生成的那把）
```

点「检查连接」，能看到模型列表就成了。

### 3. 换凭据 / 重新登录（令牌过期时）

上游令牌会过期。到期后所有请求 401，控制台顶部「令牌到期」会显示剩余天数。

换法：控制台 → **登录上游账号** → 打开登录页 → 登录完自动生效。

如果网页登录不可用（例如上游改了接口），退回「手动上传凭据」：把登录文件
拖进去即可，需要 AtRest 密钥时见下一节。

## 准备凭据

容器里**没有桌面客户端**，没法自己解密登录文件。所以凭据要靠装了客户端的
电脑提供一次。有三种方式，按方便程度排序。

### 方式 A：网页登录（推荐，不用碰命令行）

控制台 → **登录上游账号** → 点「打开登录页」。登录完成后凭据自动写入、代理自动重启。

> **账号密码不会经过你的服务器。** 流程和桌面端一致：容器只向上游申请一个
> `state` 和登录链接，你的浏览器直接和上游交互，容器只轮询「好了没」。

### 方式 B：导出明文再上传

```bash
node export-auth.mjs \
  --auth-file "<登录文件路径>" \
  --out ./data/auth.json
```

把生成的 `auth.json` 拖进控制台「手动上传凭据」。

### 方式 C：拿一次密钥，之后直接传原始登录文件

```bash
node export-auth.mjs --print-key
# 输出一串 44 字符的 Base64
```

填进控制台「设置 → AtRest 密钥」。之后可以直接把**加密的登录文件**拖进去，
控制台会用这把密钥在容器内解密。

> 这把密钥由客户端二进制派生，**同一台电脑上稳定不变**，取一次就够。

## 部署包内容

| 文件 | 作用 |
|---|---|
| `Dockerfile` | 镜像定义（两个纯 Node 文件，零依赖） |
| `docker-compose.yml` | 单容器，暴露 8790（接口）+ 8792（控制台） |
| `console.mjs` | 网页控制台 + 代理的进程管理 |
| `ai-gateway.mjs` | 代理本体（OpenAI 兼容层） |
| `export-auth.mjs` | 本地辅助：导出明文凭据 / 打印 AtRest 密钥 |
| `selftest.mjs` | 上 NAS 前在本机自检容器条件 |
| `tools/asar-grep.cjs` | 调试用：读取客户端 `app.asar` 里的接口定义 |
| `tools/stub-upstream.mjs` | 调试用：假上游，验证 429 / Retry-After 等行为 |

`selftest.mjs` 和 `tools/` 都**不进镜像**，只在本地用。

### 先自检，再部署

`selftest.mjs` 会在本机复现容器的运行条件 —— **只拷代理单文件**、用明文凭据、
把客户端路径指向不存在的位置（模拟容器里没有客户端）——然后逐项验证：
明文凭据可用、监听 0.0.0.0、局域网可连、错误令牌被拒、免费模型标了 free、
真发一次对话能出字。

```bash
node selftest.mjs "<登录文件路径>"
```

期望看到 `7/7 通过`。全绿再上 NAS，能省掉在 NAS 上盲试的时间。

## 针对 Agent 场景做的优化

这类桥接和官方 API 有几处天然差距。下面三处是实测确认、**已经修在代理里**的。

### 1. 并发按上游真实能力排队（默认 `AIGW_MAX_CONCURRENCY=1`）

实测上游对**单账号是串行处理**的：同时发 3 个请求，耗时严格递增
（2.1s → 3.7s → 5.6s）。原来的做法是把请求一股脑推上去（连接池允许 8 条），
结果上游队列越堆越长，最后一个可能要等 16 秒以上，还容易撞 429。

现在代理在本地排队：同一时刻只放 1 条到上游，其余等着。**排队发生在本地，
不产生上游副作用**。

实测对比（4 个并发请求，同一模型）：

| | 第 4 个请求耗时 | 总耗时 | 失败 |
|---|---|---|---|
| 优化前 | ~16.5s | 17.2s | 有 429 风险 |
| **优化后** | **4.7s** | **5.4s** | **0** |

控制台「设置 → 并发上限」可调（0 = 关闭闸门）。

### 2. 采样参数校验，失败方式对齐官方

上游**完全不校验**参数范围 —— `temperature=99`、`top_p=-5`、`max_tokens=0`
全都返回 200，然后模型内部按自己的方式处理。对 agent 是灾难：参数写错了
永远不报错，行为不可复现。

现在按官方规范校验，非法值直接回 400 并指明参数：

```json
{"error":{"message":"\"temperature\" must be between 0 and 2",
          "type":"invalid_request","param":"temperature"}}
```

覆盖 `temperature`(0~2)、`top_p`(0~1)、`presence_penalty`/`frequency_penalty`(-2~2)、
`max_tokens`(正整数)、`n`(仅支持 1)。

### 3. 429 时告诉调用方「多久再来」

上游 429 会带 `retry-after`，但原来没转给调用方，于是客户端只能盲重试，
常常正撞在仍在限流的窗口上。现在代理会透传 `Retry-After`（上游没给就保守
给 5 秒），并把信息接到 DSH 的 `providerRetryAfterMs` 上。

## 限制与风险

**请先读完这一节再决定是否使用。**

### 能力上的差距

| 差距 | 说明 |
|---|---|
| 无服务端工具 | 上游没有联网搜索、代码执行这类内置工具，只能用你自己的 function calling |
| 无 `logprobs` | 上游不返回逐 token 概率 |
| 部分参数无效 | `n>1`、`response_format`、`logit_bias` 等上游不真正支持；代理已改为**明确报错**而非静默接受 |
| 无 SLA | 依赖上游稳定性，没有可用性承诺，也没有工单支持 |

### 稳定性风险

- **额度共用。** 所有接入的设备消耗同一个账号额度，一端失控就全用完。
- **单账号串行。** 上游并发处理能力有限，所以代理默认把并发压到 1。
  想高并发请用官方 API。
- **随时可能失效。** 上游一旦加强客户端校验或改接口，所有请求会立刻失败。
- **模型目录不可靠。** 上游目录接口经常漏列模型，代理内置了兜底表，但不保证准确。

### 合规提醒

用订阅账号的额度给多个设备 / 程序调用，**可能不符合你订阅时的使用约定**。
请自己判断风险，尤其不要用于对外提供服务或商业项目。

### 部署安全

这个服务把额度开放到了局域网，务必注意：

1. **别直接暴露到公网**。要外网用就走反向代理 + HTTPS + 额外认证。
2. **每台设备一把 Key**，某台出问题时删掉那把就行。
3. `data/auth.json` 是明文凭据。**整个 `data` 目录别备份到公开位置**。
4. 定期检查控制台「令牌到期」，到期后全部请求会 401。

## 配置项

配置大多在网页控制台里改。需要预置的用环境变量：

| 变量 | 默认 | 说明 |
|---|---|---|
| `AIGW_PORT` | `8790` | 接口端口 |
| `CONSOLE_PORT` | `8792` | 控制台端口 |
| `AIGW_MAX_CONCURRENCY` | `1` | 同时打到上游的请求数，0 = 不限 |
| `AIGW_MAX_BODY_BYTES` | `32MB` | 请求体上限（多模态调大） |
| `AIGW_LOG` | `1` | 打印每次请求的模型/消息数（不含内容） |
| `AIGW_RATE_LIMIT_RPM` | `0` | 每分钟最多几条（0 = 不限） |
| `AIGW_CLIENT_KEYS` | 空 | 客户端 Key 列表（控制台会自动管理） |

## 运维

**以下命令都在仓库目录里执行**（`docker-compose.yml` 所在目录）。

```bash
docker compose ps                 # 状态（healthy 就正常）
docker compose logs -f            # 跟随日志
docker compose restart            # 重启
docker compose up -d --build      # 改了代码后重建

# 看额度（令牌用管理口令或任意 API Key）
curl -s http://127.0.0.1:8790/v1/quota -H "Authorization: Bearer <你的令牌>"
```

### 数据在哪

全部在仓库目录下的 `data/`（已 gitignore，不会误提交）：

| 文件 | 内容 |
|---|---|
| `auth.json` | 凭据（明文，等同账号密码，权限 600） |
| `config.json` | 管理口令、AtRest 密钥、API Key 列表 |
| `usage.jsonl` | 调用账本（每次请求的模型/token/倍率） |

**备份就备份这个目录。** 迁移到别的机器时整个拷过去即可。

### 端口冲突怎么办

改 `docker-compose.yml` 里 `ports` 的左边（宿主机侧）：

```yaml
ports:
  - "18790:8790"   # 改成别的
  - "18792:8792"
```

## 排障

| 现象 | 原因 | 处理 |
|---|---|---|
| 控制台显示「代理未运行」 | 代理起不来，通常是凭据文件坏了 | 看控制台底部「代理日志」；重新登录或上传凭据 |
| 网页登录一直「等待登录…」 | 没在浏览器完成，或链接失效 | 点「在这台设备打开」重走一遍；10 分钟会超时 |
| 网页登录报「申请登录链接失败」 | 服务器连不上上游网关 | 检查出网是否正常 |
| 客户端 401 | Key 不对，或该 Key 已被删 | 控制台重新生成一把 |
| 全部请求 401 且日志有 refresh 失败 | 凭据过期 | 网页登录一次即可 |
| 400 `code 11128` | 上游拦截了编程代理的 system 模板 | 镜像已内置降级补丁；若仍出现说明补丁丢了，`--build --no-cache` 重建 |
| 某模型 `not in the current catalog` | 上游目录漏列 | 一般能直接调用；用 `/v1/models?all=1` 看全量 |
| `docker compose build` 卡在拉镜像 | 服务器连不上 Docker Hub | 见下 |

### 拉不到基础镜像

某些网络环境访问 Docker Hub 超时，先通过镜像源拉到本地：

```bash
docker pull docker.1panel.live/library/node:22-alpine
docker tag  docker.1panel.live/library/node:22-alpine node:22-alpine
```

之后 `docker compose build` 就不会再联网。

## 支持的模型

控制台「模型」区按倍率排序显示，倍率 0 = 免费。具体列表取决于你的账号，
以控制台实际显示为准。常见的免费档位包括混元系列。

倍率是相对积分，实际扣多少还看 token 数。

## 项目结构

```
ai-gateway/
├── Dockerfile              镜像定义（只 COPY 两个 .mjs）
├── docker-compose.yml      单容器：8790 接口 + 8792 控制台
├── console.mjs             ★ 网页控制台 + 代理进程管理（一个文件）
├── ai-gateway.mjs          ★ 代理本体（OpenAI 兼容层）
├── export-auth.mjs         本地：导出明文凭据 / 打印 AtRest 密钥
├── selftest.mjs            本地：部署前自检
├── tools/
│   ├── asar-grep.cjs       调试：读客户端 app.asar
│   └── stub-upstream.mjs   调试：假上游，验证 429 行为
└── data/                   运行时生成（已 gitignore，含凭据）
```

两个 ★ 文件都是**零依赖纯 Node 程序**，只用 `node:` 内建模块，所以镜像不需要
`npm install`，也不会有依赖漂移。
